## 接下来的任务

严格按以下顺序推进。每个里程碑达到完成标准后再扩大范围。

### M1：角色与能力底层

- [ ] 定义首版角色规则：沿用原版生命、护甲和饱食度；确定灵性、战势、承压负荷、冷却、死亡与恢复。
- [ ] 确定技能输入与反馈：按键、动作栏或 HUD 提示、音效及失败原因。
- [ ] 建立服务端权威的玩家数据：途径、序列、消化度、已解锁能力和途径资源。
- [ ] 实现保存、重进世界恢复与客户端同步，并加入仅开发环境使用的测试命令。

完成标准：玩家状态可以保存和同步；单人重进世界不会丢失；客户端不能自行修改序列或资源。

### M2：铁卫序列 9 → 8

- [ ] 实现序列 9“持剑侍从”：有效近战与格挡积累战势，消耗战势发动反击重斩。
- [ ] 实现承压负荷：正常战斗可控，超额承压会短时失衡，脱战或主动卸力后恢复。
- [ ] 实现序列 8“披甲卫士”：移动格挡与连续近战产生有限临时护体。
- [ ] 加入消化度、晋升材料和晋升药剂；9 → 8 不设置大型仪式。
- [ ] 加入清楚的数值与视觉反馈，并处理自伤、友军互刷和重复触发。

完成标准：从普通人取得序列 9、完成真实战斗、消化并晋升序列 8；退出重进后进度完整。

### M3：第一段可玩闭环

- [ ] 制作一种原创怪物，包含基础行为、明显攻击前摇、至少一种弱点和有用途的掉落。
- [ ] 制作一处小型探索区域，包含目标地点、晋升材料和一个异常事件。
- [ ] 制作一份委托，完成接取、追踪、战斗或调查、结算及报酬流程。
- [ ] 加入一件带明确效果或代价的特殊物品，使其在任务中提供另一种解法。

完成标准：新角色可以连续完成“接取委托 → 探索 → 战斗 → 获得材料 → 晋升”，不依赖开发命令。

### M4：工程与联机验证

- [ ] 验证世界重载、死亡、切换维度、独立服务端和双人同步。
- [ ] 验证 GitHub Actions 构建，整理配置、日志和必要的服务端检查。
- [ ] 补充安装说明、已知问题和第三方许可清单，生成首个内部测试包。

完成标准：干净环境可构建和安装；两名玩家完成同一委托时状态互不串扰，无客户端越权修改。

### M5：横向验证三条途径

- [ ] 实现烛灵序列 9 的烛焰箭、灯罩屏障和一只低阶灯蛾。
- [ ] 实现歧路序列 9 的有限偏运、一次战斗机会和一次探索机会。
- [ ] 让三条途径以同级装备挑战同一区域，比较操作、强度和非战斗解法。

完成标准：三条途径有不同的战斗循环和至少一种非战斗用途，没有任何一条同时包揽承伤、输出、控制与探索。

## 首轮暂不制作

基础经济、日常职业、完整图鉴、宠物、坐骑、其他维度、高序列和大型主线均不进入第一段原型。首轮只保留任务结算所需的报酬和一个简单怪物信息提示，不提前建设完整系统。
